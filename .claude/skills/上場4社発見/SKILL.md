## 調査条件(厳守)

### 4. 期間の制約

- それより古い情報は「参考情報(期間対象外・過去の実績)」として分けて記載する

## 実行手順

1. 4社について、Agent(general-purpose)を並列で4体起動する。各エージェントには以下を指示する:
   - 対象企業1社
   - 上記の3セグメント×4チャネルの調査
   - 上記の情報源制約・期間制約を厳格に守ること
   - 推測・創作は禁止。情報が見つからない項目は「情報未確認」と明記すること
   - 出力はMarkdown形式のテキストで返却(エージェント自身はファイル作成不要)

2. 4体の結果が出揃ったら、各社ごとに以下のファイルを更新する(上書き):
   - `日本M&Aセンターホールディングス(2127)_施策調査メモ_直近6ヶ月版.md`
   - `M&Aキャピタルパートナーズ(6080)_施策調査メモ_直近6ヶ月版.md`
   - `ストライク(6196)_施策調査メモ_直近6ヶ月版.md`
   - `クオンツ総研ホールディングス(9552)_施策調査メモ_直近6ヶ月版.md`
   - ファイル冒頭に「調査日」を実行日で更新すること

3. 4社分の比較サマリーを更新する:
   - `M&A仲介4社_施策比較メモ_直近6ヶ月版.md`
   - セグメント別の最重要トピック、前回調査結果との変化点(新規提携・新規セミナー・新規メディア展開など)を明記する
   - 「今後のセミナー予定一覧(4社横断・日付順)」の表を更新する: 各社メモのセミナー欄から開催日が特定できたものを日付順に並べる(企業・セグメント・セミナー名・形式の列)。実行日より前の(既に終了した)回は表から削除し、新たに確認できた開催予定を追記する。開催日が特定できないセミナー(オンデマンド視聴のみ等)は表に含めず、表の下の注記に記載する

4. 変更をコミット・pushする際は、**`main`ブランチへ直接pushしない**こと。`main`には人間が行ったコミットが既に存在するため、Claude GitHub Appの既定ルールにより直接pushが拒否される。代わりに以下の手順を踏む:
   - `git fetch origin && git checkout -B claude/上場4社発見-latest origin/main`(毎回originのmainを起点に作り直す)
   - ファイル更新後、`git add -A && git commit -m '定期調査 YYYY-MM-DD: 上場4社発見'`
   - `git push -f origin claude/上場4社発見-latest`
   - 最新の調査結果は `claude/上場4社発見-latest` ブランチに反映される。ユーザーがGitHub上でこのブランチを確認し、必要に応じて`main`へマージする運用とする

5. ユーザーへの報告は簡潔に: 各セグメントで新たに確認できた主要トピックを3〜5個、箇条書きで提示する(全文の再掲は不要)。あわせて更新結果が `claude/上場4社発見-latest` ブランチにpushされた旨を伝える

6. Gmail MCP(create_draft)で、以下の内容の下書きを作成する。**送信はしない**(送信機能が存在しないため下書き作成のみ):
   - 宛先: bsscjigyousyoukei@gmail.com
   - 件名: `上場4社発見: 定期調査完了(YYYY-MM-DD) - 手動で確認してください`
   - 本文: 手順5で報告した主要トピック(3〜5個の箇条書き)と、「claude/上場4社発見-latest ブランチにpush済み。GitHub (https://github.com/bsscjigyousyoukei-eng/-/tree/claude/上場4社発見-latest) で内容を確認し、必要であればmainへマージしてください」という一文を含める

### 既知の技術的制約(調査時に留意)
- X(旧Twitter)はWebFetchで直接アクセス不可なケースが多い(402エラー等)→ WebSearch経由で補完するか、投稿日が特定できない場合は「情報未確認」とする
- YouTube公式チャンネルはSPA構造のためページ取得だけでは動画一覧が取れない → RSSフィード(`https://www.youtube.com/feeds/videos.xml?channel_id=xxxx`)の利用を検討する
- Instagram/Facebookはプロフィール情報は取得できてもタイムラインが取得できないことが多い
- 決算説明資料PDFが画像ベースでテキスト抽出できないことがある
- 【重要】クラウド実行環境(claude.ai/code/routines)では、セッションによってはネットワークegressポリシーにより主要ドメイン(各社公式サイト・prtimes.jp・youtube.com・x.com・facebook.com・instagram.com等)へのWebFetchが全面ブロックされることがある(2026/8/11実行時に発生)。その場合はWebSearchのスニペットのみでの調査となり確度が下がるため、各メモにその旨を明記し、「情報未確認」を安易に「変化なし」と解釈しないこと
